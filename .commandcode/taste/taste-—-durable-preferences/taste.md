# Taste — durable preferences
- Prefers complete, runnable implementations over tutorials, pseudocode, partial implementations, or architecture-only answers; deliver working code and real files, not explanations. Confidence: 0.95
- Prefers a smaller but fully working MVP over a large set of incomplete abstractions; no TODO placeholders for core features. Confidence: 0.95
- Prefers implementing the core application first and deferring content/data authoring ("worry about questions later"). Confidence: 0.7
- Treats the task as done only when the full verification gate passes: lint, type-check, content validation, unit tests, production build (and E2E where applicable), then a concise final report. Confidence: 0.9
- Prefers TypeScript in strict mode. Confidence: 0.9
- Prefers clean, feature-oriented modules and explicitly avoids giant components. Confidence: 0.85
- Prefers typed contracts between layers (e.g., a typed message protocol for workers/APIs). Confidence: 0.8
- Prefers comments only where implementation choices are non-obvious; no excessive commenting. Confidence: 0.85
- Prefers not hard-coding domain logic inside UI components; generic, configurable logic over question/feature-specific branching. Confidence: 0.8
- Prefers minimal dependencies and maintained, browser-compatible libraries over convenience packages. Confidence: 0.8
- Prefers meaningful tests over placeholders (unit + end-to-end + a content/data validation script). Confidence: 0.9
- Prefers CI wiring (e.g., GitHub Actions) that runs install, lint, type-check, content validation, tests, and build on PRs. Confidence: 0.85
- Prefers local-first, backend-free architectures when the product permits (data and execution stay in the browser). Confidence: 0.8
- Cares about bundle performance: lazy-load heavy libraries (editors, WASM runtimes), keep them out of landing/catalogue payloads, statically generate pages. Confidence: 0.85
- Prefers executing expensive work off the main thread (Web Workers) with timeouts and kill/recreate semantics rather than freezing the UI. Confidence: 0.75
- Prefers static-first, Vercel-friendly deployment with no server-side secrets or functions when possible. Confidence: 0.7
- Prefers accessible, keyboard-operable UI: accessible labels, keyboard shortcuts, loading skeletons, and clear empty/error states. Confidence: 0.8
- Prefers dark mode + light mode support driven by system preference with a user toggle. Confidence: 0.75
- Prefers honest, explicit documentation of security/limitations (e.g., "bundled test fixtures are not secret") rather than hiding them. Confidence: 0.85
- Prefers a strong README: product overview, architecture, tech stack, setup, commands, authoring guide, deployment steps, and a future roadmap. Confidence: 0.85
- Prefers npm as the package manager. Confidence: 0.7
